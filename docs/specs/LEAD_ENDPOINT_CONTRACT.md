## 1. Conventions

- Field names, codes and identifiers: English, `snake_case`. Encoding: UTF-8.
- Visitor-facing text never comes from the response. The frontend maps `error_code` and field error codes to localized copy (`docs/ux/CONTENT.md` §Form).
- **Apps Script web apps always answer HTTP 200** (they cannot set status codes). The **response body is the source of truth**. A future backend (ADR-002) must return the same body; it may also use HTTP status codes, and clients must not depend on them.

## 2. Endpoint

| Item | Value |
|---|---|
| Method | `POST` |
| URL | The Apps Script deployment URL `https://script.google.com/macros/s/<deployment_id>/exec`, provided to the frontend as `PUBLIC_LEAD_ENDPOINT_URL` (public by design; not a secret) |
| Request header | `Content-Type: text/plain;charset=utf-8` — **no other custom headers**. This keeps the request a CORS "simple request" (no preflight, which Apps Script cannot answer). The body is a JSON string. |
| Fetch options | `method: "POST"`, `redirect: "follow"`, `credentials: "omit"`. Apps Script answers with a 302 to `script.googleusercontent.com`, which returns the JSON with `Access-Control-Allow-Origin: *`. |
| Response content type | `application/json` (via `ContentService.MimeType.JSON`) |
| Max body | 10 KB (larger → `payload_too_large`) |
| Client timeout | 20 s; on timeout the client shows the network error state (§7) |
| Authentication | None (public form). Apps Script deployment: *Execute as: Me (owner)*, *Who has access: Anyone*. |

## 3. Request body

```json
{
  "name": "Ana María Pérez",
  "email": "ana.perez@example.com",
  "phone": "+506 8888 0000",
  "company": "Panadería La Esquina",
  "project_type": "web_app",
  "budget_range": "from_1000_to_3000",
  "timeline": "within_3_months",
  "message": "Quiero un catálogo en línea con pedidos por WhatsApp para mi panadería.",
  "language": "es",
  "consent": true,
  "privacy_notice_version": "2026-10-14-v1",
  "submission_id": "8f14e45f-ceea-4e7a-9b1c-3f0a2d5c7e21",
  "website": "",
  "elapsed_ms": 48250
}
```

| Field | Type | Required | Rules (client AND server) | Stored as |
|---|---|---|---|---|
| `name` | string | yes | Trim; collapse inner whitespace. 2–100 characters. Unicode letters, spaces, `'` `’` `-` `.` only. | normalized |
| `email` | string | yes | Trim, lowercase. ≤ 254 chars; must match `^[a-z0-9._%+-]+@[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?(?:\.[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?)*\.[a-z]{2,63}$`; local part must not start/end with `.` or contain `..`. | normalized |
| `phone` | string \| null | no | Empty/absent → `""`. Otherwise strip spaces, `-`, `(`, `)`, `.`; result must match `^\+?[0-9]{7,15}$`. | normalized or `""` |
| `company` | string \| null | no | Trim; ≤ 100 chars. Empty/absent → `""`. | trimmed or `""` |
| `project_type` | string (enum) | yes | §4.1 | code |
| `budget_range` | string (enum) | yes | §4.2 | code |
| `timeline` | string (enum) | yes | §4.3 | code |
| `message` | string | yes | Trim. 20–2000 characters. Line breaks allowed. | trimmed |
| `language` | string (enum) | yes | `es` or `en` (page language at submit time). | code |
| `consent` | boolean | yes | Must be JSON `true`. | `TRUE` |
| `privacy_notice_version` | string | yes | The version of the notice shown next to the consent checkbox. Must be one of Script Property `ACCEPTED_PRIVACY_NOTICE_VERSIONS` (comma-separated) → else `invalid_option`. | as sent |
| `submission_id` | string | yes | UUID v4 generated by the client once per form instance and **reused on every retry** of the same submission; a new one only after a success. Must match `^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$` (lowercase). Idempotency key (§5.4). | as sent |
| `website` | string \| null | no | Honeypot (§5.1). Never stored. | — |
| `elapsed_ms` | integer | yes | Milliseconds between the form's first render and the submit click, measured on the client with a monotonic clock (`performance.now()`), so client/server clock skew cannot affect it. 0 – 86 400 000. Used for the minimum fill time (§5.2). Never stored. | — |

Unknown fields are ignored. Wrong JSON types are validation errors (`invalid_type`).

Spreadsheet formula injection: any stored text value starting with `=`, `+`, `-` or `@` is prefixed with an apostrophe `'` before writing (applies to `name`, `company`, `message`, `phone`).

## 5. Processing order (server)

1. Body larger than 10 KB → `payload_too_large`.
2. Body is not valid JSON or not an object → `invalid_json`.
3. **Honeypot** (§5.1) → decoy success, stop.
4. Field validation (§3), including `elapsed_ms` and `submission_id` → `validation_failed` with every field error.
5. **Minimum fill time** (§5.2) → decoy success, stop.
6. Acquire the script lock (`LockService`, wait ≤ 10 s; timeout → `storage_unavailable`). Steps 7–9 run under the lock.
7. **Idempotency** (§5.4): `submission_id` already in column R → respond the original success, stop.
8. **Throttles** (§5.3) → `rate_limited`.
9. Append the row (§6) and release the lock. Failure → `storage_unavailable`.
10. Send the owner notification, then the visitor confirmation (ADR-005), each only if `MailApp.getRemainingDailyQuota()` ≥ 1 (else status `quota_exceeded`). Each failure is caught, recorded in the row (`owner_email_status` / `confirmation_email_status` = `failed`), and does **not** change the response.
11. Respond success.

### 5.1 Honeypot
`website` absent, `null` or empty after trim → normal. Any other value or type → bot: respond the normal success body with a random `lead_id`, store nothing, send nothing.

### 5.2 Minimum fill time
A valid `elapsed_ms` below 3000 → treated as a bot (decoy success, nothing stored, no email). Because it is a client-measured duration, no server clock comparison is involved.

### 5.3 Throttles (durable: counted from the sheet)
Counted under the script lock from the stored rows themselves (columns A and E of the most recent rows, at most `MAX_LEADS_PER_DAY` + 1 rows read), so they cannot be bypassed by cache eviction and need no extra storage. CacheService may be used only as a read optimisation, never as the source of truth.
- Per email: at most `MAX_LEADS_PER_EMAIL_PER_HOUR` (default 3) stored leads with the same normalized email in the last 60 minutes.
- Global hourly: at most `MAX_LEADS_PER_HOUR` (default 20) stored leads in the last 60 minutes.
- Global daily: at most `MAX_LEADS_PER_DAY` (default 40, i.e. 80 email recipients, below the ~100/day consumer Gmail quota) stored leads on the current calendar day in America/Costa_Rica.
- Independently, emails are sent only while `MailApp.getRemainingDailyQuota()` ≥ 1 (step 10); a lead is never rejected because of email quota.
- Exceeded → `rate_limited` with `retry_after_seconds` (seconds until the window or the day resets). Apps Script cannot see the client IP; no IP is ever stored.

### 5.4 Idempotency (durable)
- The source of truth is column R of the sheet. Under the script lock, the server looks the `submission_id` up in column R (exact, whole-cell match, e.g. `TextFinder.matchEntireCell(true)`); a CacheService entry may short-circuit the lookup but a cache miss always falls back to the sheet, whatever the age of the original lead.
- A request whose `submission_id` is found returns `{ "ok": true, "lead_id": <lead_id of that row> }` and stores and sends nothing.
- Tests cover: retry after a cache miss, retry hours later, and two concurrent requests with the same `submission_id` (exactly one row).
- The client keeps the same `submission_id` for retries after a timeout, network error, `storage_unavailable` or `internal_error`, so a lost response never creates a duplicate lead or duplicate emails. The client generates a new `submission_id` only after a success (or a page reload).

## 6. Google Sheet

Spreadsheet: owned by the owner's Google account; worksheet name `leads`. Row 1 is the header with **exactly** these columns, in order:

| # | Column | Value |
|---|---|---|
| A | `submitted_at` | Server time in `America/Costa_Rica`, formatted `yyyy-MM-dd HH:mm:ss` |
| B | `status` | `new` on creation. Data-validation dropdown: `new`, `contacting`, `accepted`, `rejected` |
| C | `lead_id` | `DS-` + `yyyyMMdd` + `-` + 6 random uppercase alphanumerics, e.g. `DS-20261014-K7Q2XM` |
| D | `name` | normalized |
| E | `email` | normalized |
| F | `phone` | normalized or empty |
| G | `company` | trimmed or empty |
| H | `project_type` | code |
| I | `budget_range` | code |
| J | `timeline` | code |
| K | `message` | trimmed |
| L | `language` | `es` / `en` |
| M | `consent` | `TRUE` |
| N | `privacy_notice_version` | as sent by the client (validated against `ACCEPTED_PRIVACY_NOTICE_VERSIONS`) |
| O | `owner_email_status` | `sent` / `failed` / `skipped` / `quota_exceeded` |
| P | `confirmation_email_status` | `sent` / `failed` / `skipped` / `quota_exceeded` |
| Q | `notes` | empty; for the owner's manual notes |
| R | `submission_id` | as sent (idempotency key) |
| S | `last_contact_at` | empty on creation; the owner writes the date (`yyyy-MM-dd`) of each later contact. Retention (PROJECT_SPEC §7) counts 24 months from this date, or from `submitted_at` while it is empty |

`skipped` is used when the email is disabled by configuration (`SEND_EMAILS=false`). Rows are appended; after creation the script only fills columns O and P (email outcome) and never edits `status`, `notes` or `last_contact_at`.

## 7. Response body

Success (also the decoy success):
```json
{ "ok": true, "lead_id": "DS-20261014-K7Q2XM" }
```

Error:
```json
{
  "ok": false,
  "error_code": "validation_failed",
  "message": "One or more fields are invalid.",
  "field_errors": { "email": "invalid_format", "message": "too_short" }
}
```

| `error_code` | When | Extra fields | Frontend behaviour |
|---|---|---|---|
| `validation_failed` | §3 rules | `field_errors` | Show localized error per field; keep data |
| `invalid_json` | Unparseable body | — | Generic error + retry |
| `payload_too_large` | > 10 KB | — | Generic error |
| `rate_limited` | §5.3 | `retry_after_seconds` | "Too many attempts" message; keep data |
| `storage_unavailable` | Sheet write failed | — | "Could not send, try again or email us" with mailto fallback; keep data |
| `internal_error` | Anything unexpected | — | Same as `storage_unavailable` |

Field error codes: `required`, `invalid_type`, `too_short`, `too_long`, `invalid_format`, `invalid_option`, `must_be_true`.

Network failure, timeout, non-JSON response or a body without boolean `ok` → the frontend treats it as `internal_error`.

`message` is a short English string for troubleshooting only; never shown to visitors.

## 9. Local mock
